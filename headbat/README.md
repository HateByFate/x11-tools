# headbat

Заряд наушников **Logitech G435** в трее GNOME + уведомления о низком заряде.

G HUB не поддерживает G435, а стандартный UPower заряд этого донгла не отдаёт.
headbat читает заряд по реверс-инженеренному HID-протоколу и показывает процент
рядом с часами.

## Возможности

- Иконка наушников в трее с подписью-процентом (Ayatana AppIndicator).
  Заряд дублируется в `Title` индикатора — виден в подсказке и меню, даже если
  тема панели прячет подпись.
- Уведомления: подключение/отключение, низкий заряд (≤20% и ≤10%).
- Разовый вывод: `headbat --status` → `57% (3813 мВ)`.
- Меню трея с пунктом «Выход».

## Важно: пауза звука при чтении (и почему «тихого» опроса не бывает)

У G435 **нет тихого способа** спросить заряд. Донгл `046d:0acb` (ревизия
HDT647 — самая распространённая, в том числе ваша) для ответа уходит в
сервисный режим «bootloader» моста Realtek, и прошивка **глушит звук и микрофон
примерно на 0.6 секунды при каждом чтении**. Обойти это нельзя — ограничение
прошивки донгла, а не ours-кода. Это же подтверждает автор эталонного проекта
[deddroid/logitech-g435-battery](https://github.com/deddroid/logitech-g435-battery)
в своём `README` и `docs/PROTOCOL.md`.

Бывает и **новый донгл `046d:0adf`** (другая ревизия, 64-байтовые репорты с
CRC-16): на нём чтение не прерывает звук (проверено на железе в Windows-проекте
`portyporty/g435-battery-percentage`). Но:
- у вас стоит именно `0acb` (проверено: `lsusb | grep 046d` → `046d:0acb`);
- поддержка `0adf` в открытом коде помечена как *ported, untested*;
- наш HID-транспорт заточен под `0acb` (report 6 через Realtek-мост). Для
  `0adf` нужен другой транспорт и отдельный донгл с переспариванием — это
  отдельная задача, здесь не реализовано.

Поэтому Strategies простая: **опросить как можно реже и в момент тишины**.
Конкретная логика (та же, что в g435-tray):

- по умолчанию опрос **раз в 15 минут** (`--interval`), первый опрос — сразу
  при старте, чтобы трей не был пустым;
- пока наушники играют звук (проверка через `pactl`), плановый опрос
  **пропускается**, а в трей продолжает показываться последнее значение;
- если звук идёт **дольше 30 минут подряд** (`--max-silence-wait`), опрос всё
  равно выполняется — лучше один раз пожертвовать 0.6 с звука, чем показывать
  совсем устаревший заряд;
- после неудачного чтения повтор через 10 с, а не через 15 мин;
- опрос можно переопределить вручную: `--always` — не ждать тишины вообще;
  таймер тишины сбрасывается, как только звук прекратился.

Частый опрос батарею почти не сажает (радиообмен — доли миллисекунды), вредит
именно пауза звука.

## Сборка и установка

Нужны только `gcc` и `make` — GTK/appindicator/libnotify грузятся через
`dlopen`, заголовки не требуются (рантайм-библиотеки в Debian с GNOME стоят по
умолчанию).

```sh
make -C ~/x11-tools            # собрать всё, включая headbat
make -C ~/x11-tools install    # ~/.local/bin/headbat + автозапуск GNOME + иконка
make -C ~/x11-tools test       # автотесты (для headbat — protocol, без железа)
```

### Доступ к донглу без root (обязательно)

Донгл `046d:0acb` создаёт `/dev/hidraw*` с правами только root. Чтобы headbat
читал заряд от обычного пользователя, установите udev-rule (нужен sudo):

```sh
sudo install -Dm644 headbat/70-headbat.rules /etc/udev/rules.d/70-headbat.rules
sudo udevadm control --reload && sudo udevadm trigger
```

Правило выдаёт доступ активному локальному пользователю через `TAG+="uaccess"`.

## Запуск

```sh
headbat                            # демон: трей + уведомления, 15 мин, ждёт тишины
headbat --status                   # один раз вывести заряд и выйти
headbat --interval 60              # опрос раз в минуту (секунды)
headbat --max-silence-wait 300     # ждать тишины не дольше 5 минут
headbat --always                   # не пропускать опрос при звуке
headbat --no-tray                  # без иконки в трее (только уведомления)
headbat -v                         # подробный лог в stderr
headbat --help                     # справка
```

Автозапуск GNOME ставится `make install`
(`~/.config/autostart/headbat.desktop`). После правки C-кода достаточно
пересобрать и перезапустить демон; правки `opencode.jsonc`/`cli.json`
перезапуска OpenCode не требуют.

## Как это работает

1. Поиск hidraw-узла донгла `046d:0acb` через sysfs (`HID_ID`).
2. Чтение заряда по протоколу моста Realtek ALC4021 → SoC Airoha PAU1823:
   - вход в «bootloader» (`06 01 03`);
   - статус подключения (`REMOTE_GET_CONNECT_STATUS`) — **всегда первым**;
   - напряжение аккумулятора (`GET_BATTERY`, милливольты);
   - если донгл в режиме 0 и отвечает мусором — `REMOTE_SET_MODE 1` и повтор;
   - выход из bootloader (`06 08 03`) — всегда, даже при ошибке;
   - **всё это и есть причина 0.6 с тишины** — донгл физически не может
     ответить на GET_BATTERY, оставаясь в аудиорежиме.
3. Пересчёт милливольт→проценты по кусочной кривой Li-Po.
4. Обновление трея: `XAyatanaLabel` и `Title`. Метка выставляется повторно
   раз в 2 с с чередованием завершающего пробела — это заставляет libayatana
   слать `PropertiesChanged`, иначе расширение appindicators может пропустить
   первое значение и подпись останется пустой.

**GET_BATTERY никогда не отправляется первой командой** — иначе донгл может
зависнуть до переподключения (известный баг прошивки). Команды идут как
514-байтовые output-репорты (быстро, ~14 мс), ответы читаются GET_FEATURE.
