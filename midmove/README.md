# midmove

Перетаскивание окна **kitty** средней кнопкой мыши.

Зажали среднюю кнопку и ведёте указатель — окно едет. Отпустили — перетаскивание
закончилось. Короткий клик без движения остаётся обычной средней кнопкой, то есть
в kitty работает вставка.

```
зажал среднюю ──► веду указатель ──► окно едет
отпустил     ──► окно осталось там, где отпустил
кликнул      ──► вставка из primary selection
```

## Зачем это нужно

- В конфиге kitty стоит `hide_window_decorations yes`, поэтому у окна нет заголовка,
  и двигать его можно только Alt+drag — это делает mutter, а не kitty.
- В GNOME нет настройки «двигать окно средней кнопкой»: ключ
  `org.gnome.desktop.wm.preferences mouse-button-modifier` принимает только
  клавиши-модификаторы (`<Alt>`, `<Super>` …), а кнопки мыши парсер mutter
  (`meta_parse_modifier()`) не понимает.
- В kitty такой возможности тоже нет: `mouse_map` умеет только действия внутри
  терминала (`mouse_handle_click`, `mouse_selection`, `paste_from_selection`,
  `discard_event`, `mouse_show_command_output`), а `move_window`/`resize_window`
  в kitty — это про панели внутри вкладки, а не про окно ОС.

Значит, нужен отдельный процесс, который перехватывает среднюю кнопку и передаёт
перетаскивание оконному менеджеру.

## Как это работает

1. **Пассивный захват кнопки.** `XGrabButton` на корневом окне для `Button2`
   в четырёх комбинациях модификаторов: без них, с CapsLock, с NumLock и с обоими.
   Поэтому Shift/Ctrl/Alt/Super+средняя не перехватываются вовсе.

2. **Нажатие в окне kitty** (определяется по `WM_CLASS=kitty`) остаётся у программы,
   указатель расмораживается (`XAllowEvents(AsyncPointer)`), и программа ждёт:
   будет движение или это просто клик.

3. **Движение больше порога** (по умолчанию 3 px) — окно передаётся mutter'у через
   EWMH-сообщение `_NET_WM_MOVERESIZE` (`action=MOVE`, `button=2`). Дальше окно
   тащит сам оконный менеджер: плавно, с прилипанием к краям, тайлингом и т. п.

4. **Завершение по отпусканию.** Здесь есть подвох: mutter завершает перетаскивание
   только по отпусканию 1-й или 3-й кнопки
   (см. `process_pointer_event()` в `src/compositor/meta-window-drag.c`:
   `if (button == 1 || button == meta_prefs_get_mouse_button_resize())`), а любое
   другое нажатие просто сбрасывает захват. Поэтому отпускание средней кнопки
   отслеживается опросом `XQueryPointer` раз в 8 мс, и в момент отпускания
   отправляется `_NET_WM_MOVERESIZE_CANCEL` → mutter аккуратно вызывает
   `meta_window_drag_end()`. Без этого получается «тумблер»: окно продолжало бы
   ехать за указателем до следующего нажатия.

5. **Клик без движения** переиздаётся через XTest (`XTestFakeButtonEvent`), поэтому
   вставка средней кнопкой в kitty работает. Для kitty это даже незаметно: она
   по умолчанию вставляет на отпускании
   (`mouse_map middle release ungrabbed paste_from_selection`).

6. **Чужие окна не трогаются.** Если нажатие пришлось не на kitty, оно сразу
   отдаётся приложению через `XAllowEvents(ReplayPointer)` — там средняя кнопка
   работает полностью штатно (вставка на нажатии, средний драг и т. п.).

Схема:

```
физическое нажатие Button2
        │
        ├── окно не kitty ───► ReplayPointer ───► приложение работает как обычно
        │
        └── окно kitty
               ├── движение > порога ──► _NET_WM_MOVERESIZE(button=2) ──► mutter тащит
               │                                  │
               │                                  └── отпустили ──► _NET_WM_MOVERESIZE_CANCEL
               │
               └── отпустили без движения ──► клик через XTest ──► вставка
```

## Сборка и запуск

```sh
make -C .. install    # в ~/.local/bin + автозапуск GNOME
# или вручную:
gcc -O2 -Wall -Wextra -o midmove midmove.c -lX11 -ldl

./midmove             # запустить
./midmove -v          # то же, но писать в stderr, что происходит
./midmove -t 8        # порог старта перетаскивания в пикселях (по умолчанию 3)
```

Остановить: `pkill -x midmove`.

## Ограничения

- **Только X11.** В Wayland-сессии глобально перехватить кнопку и двигать чужое окно
  нельзя — утилита там не заработает.
- Работает **только с окнами kitty** — сделано намеренно, чтобы не менять поведение
  мыши в остальных приложениях.
- Внутри окна kitty средний драг тоже становится перемещением окна: приложения
  в терминале, которые используют «средний драг» (некоторые TUI в mouse-режиме),
  этого не получат.
- Клик без движения приходит в kitty в момент отпускания кнопки, а не нажатия
  (плюс единицы миллисекунд). Для kitty это незаметно, см. п. 5.
- Если у kitty включены заголовки (`hide_window_decorations no`), тоже работает:
  перетаскивание делает mutter, рамки он учитывает сам.
- Два экземпляра одновременно не запустятся: второй пишет
  `midmove: уже запущен (кнопка 2 уже захвачена), выходим` и завершается.

## Нагрузка

Замер на Debian 13 / X11 (по `/proc/<pid>/stat`):

| Режим | CPU | Память |
| --- | --- | --- |
| простой | 0.00 % | ~2.6 МБ |
| перетаскивание (600 событий за 7.5 с) | ~0.5 % одного ядра | не растёт |

Опрос указателя идёт только пока окно тащат.

## Тесты

В `tests/` лежат программы, которые создают окна и подают **настоящие** события мыши
через XTest — то есть проверяют утилиту так же, как это делает человек.

| Тест | Что проверяет |
| --- | --- |
| `midmove_test.c` | kitty-окно сдвигается ровно на сдвиг указателя (96,48 при ожидаемых 96,48); клик доходит до окна (вставка); чужое окно не двигается и получает нажатие сразу |
| `drag_end_test.c` | после отпускания кнопки окно больше не двигается |
| `drag_stress.c` | длинное перетаскивание (600 шагов) — для замера нагрузки |

```sh
make -C .. test        # сам поднимет midmove и погасит его
make -C .. tests       # только собрать тесты в bin/
```

Требуется запущенный X-сервер и `libXtst.so.6`.

## Проверено на

Debian 13 (trixie), GNOME 48.7 / mutter 48.7, kitty 0.41.1, X11.

## История

Изначальная задача: «двигать окно kitty средней кнопкой, пока держишь».
Первая рабочая версия отдавала перетаскивание через `_NET_WM_MOVERESIZE`, и получался
«тумблер»: mutter не завершает такой drag по отпусканию средней кнопки, окно ехало
за указателем до следующего нажатия. Решение — `_NET_WM_MOVERESIZE_CANCEL` по
отпусканию, см. п. 4.
